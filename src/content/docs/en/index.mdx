You can start without writing code: read the lectures and do each chapter's Try it first and self-check, and you will understand how AI systems work (the concepts route). The exercises need basic programming, HTTP and JSON (the hands-on routes).

Every chapter reads two ways, switchable at the top of the page: **Simple** shows only the main line, written to make sense on a first read; **Deep** opens the implementation details, derivations, optional topics and advanced exercises.

## What the system project leaves you with

The system project is made up of the chapters' advanced exercises. Finish it and you have a deployed agent you use every day, with RAG, tools, memory, evals and security guardrails, plus engineering evidence you can hand to someone for review. Each chapter grows one capability (the number after A matches the chapter number; see [How to read the codes](/en/guide/how-to-use/#how-to-read-the-codes)):

| Stage | What your system gains |
|---|---|
| Part II Applications (A6–A8) | A streaming chat UI (Gradio, Chainlit or a CLI work too) with traces, reliable structured output and workflows, and a golden set and judge grown from real traces |
| Part III Knowledge & Tools (A9–A11) | RAG with citations, tools and an MCP server with risk levels, and a context builder with a budget and caching |
| Part IV Agents (A12–A15) | A hand-written harness, layered memory, trajectory evals and prompt optimization; multi-agent stays only if it wins the eval |
| Part V Production (A16–A18) | A security audit and fixes, a complete frontend, and a multi-user deployment with an eval-gated release process |
| Part VI Capstone (A19) | The capstone: extend it into an always-on agent |

The full breakdown is in [System Project A6–A19](/en/projects/system-thread/#what-each-chapter-adds).
